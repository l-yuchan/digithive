# digithive 개인용 인지 비서

계획서의 핵심 경험을 혼자 한 달 동안 검증하는 로컬 프로토타입입니다.
관심·사실·가설·약속·위임을 구분해 저장하고, 직접 입력한 새 근거가
관심의 장애물과 연결되면 검토할 제안을 만듭니다.

## 실행

Bun 1.4.4 이상이 필요합니다. 프로젝트 폴더에서 실행하세요.

```sh
bun install
bun run start
```

브라우저에서 `http://127.0.0.1:3000`을 여세요. 시작 명령은 화면을 빌드한 뒤
서버를 실행합니다. 종료는 터미널에서 Ctrl+C입니다.

```sh
bun run verify
```

위 명령은 타입 검사, 화면 빌드, 전체 테스트를 실행합니다. 개발 시에는
먼저 `bun run build:ui`, 이후 `bun run dev`를 실행하세요.
프런트엔드를 고친 뒤에는 `bun run build:ui`를 다시 실행해야 합니다.

## 첫 사용

1. **내 기록 → 생각 기록**에서 관심을 선택합니다. 원문, 중요한 이유,
   현재 장애물, 적용 범위(예: `research`)를 남기세요.
2. **자료와 변화**에서 직접 읽은 출처와 근거 요약을 추가합니다.
   이후 **새 변화 기록**으로 무엇이 달라졌는지 입력합니다.
3. **제안 검토**에서 원래 기록·출처·일치어·불확실성을 확인하고
   수락, 거절, 보류, 정정 중 하나를 선택합니다.
4. **오늘**에서 저장 기록을 질문으로 찾을 수 있습니다.
   관심이나 가설을 확정된 결정으로 보고하지 않습니다.
5. **설정**에서 조용 모드, 집중 시간, 범위별 선호를 정하세요.
   `global`은 공통 기본값이며 기록과 선호의 범위 이름을 맞춰야 합니다.
6. **한 달 일지**에서 기준선/비서 조건과 실제 노력을 기록합니다.
   미측정 시간은 빈칸으로 두세요. 0분과 결측은 다릅니다.

수락만으로 약속은 생기지 않습니다. **내 기록 → 약속·위임 만들기**에서
별도로 승인해야 새 기록이 만들어집니다. 외부 일정은 바뀌지 않습니다.
로컬 준비 요청은 대기 상태로 저장되며 **저장 자료로 준비 실행**을 눌러야
진행합니다. 실행 전 중단할 수 있고 실제 수행한 단계가 남습니다.

## 기능의 범위

- SQLite에 원문·정정·추적 상태·출처·제안·선호·평가·이력을 저장합니다.
- 관련성은 한국어를 포함한 토큰 겹침과 장애물 연결 규칙으로 판단합니다.
- 약한 연결은 조용히 보관하고 강한 연결만 제시합니다.
- 조용 모드는 시급한 제안도 보류합니다. 앱이 열려 있지 않을 때
  백그라운드 알림을 보내지 않으며, 다시 열어 검토할 때 상태를 갱신합니다.
- 거절한 동일 제안은 반복하지 않습니다. 정정은 기존 제안을 만료시키고,
  추적 중단은 관련 준비와 제안을 중단합니다.
- 실제 이메일·일정 변경·구매·외부 조사·자동 웹 수집은 없습니다.
- **LLM 연동은 이 버전에 없습니다.** 계정이나 API 키가 필요하지 않습니다.
  규칙은 의미를 이해하지 못하므로 유용한 연결을 놓치거나 피상적 연결을
  만들 수 있습니다. 설명·초안은 저장 기록에 기반한 템플릿입니다.

## 데이터와 백업

기본 데이터: `data/digithive.sqlite`. 서버는 `127.0.0.1`에 바인딩됩니다.
`DIGITHIVE_DB`, `DIGITHIVE_PORT`, `DIGITHIVE_BACKUP_DIR`로 경로와 포트를
바꿀 수 있습니다. 암호화·동기화·다중 사용자 인증은 제공하지 않습니다.

**기록 · 백업** 화면에서:

- **전체 JSON 내보내기**: 모든 기록의 열람·분석용 사본을 다운로드합니다.
  JSON 가져오기 기능은 없습니다.
- **SQLite 스냅샷 생성**: `backups/`에 독립 데이터베이스 파일을 만듭니다.
  `VACUUM INTO`를 사용하므로 실행 중인 DB의 WAL 파일을 수동 복사할
  필요가 없습니다.
- **전체 데이터 삭제**: `DELETE_ALL` 입력 후 현재 DB를 초기화합니다.
  이미 다운로드하거나 생성한 백업 파일은 별도로 남습니다.

### 복원

서버를 종료한 후, 원본 백업을 보존하기 위해 스냅샷을 **새 파일명**으로
복사하고 그 파일을 데이터베이스로 지정하세요. 기존 DB나 WAL 파일을
덮어쓰지 않습니다.

PowerShell 예:

```powershell
Copy-Item "backups/실제-스냅샷-파일.sqlite" "data/restored.sqlite"
$env:DIGITHIVE_DB = "data/restored.sqlite"
bun run start
```

`restored.sqlite`는 기존에 없는 파일명을 사용하세요. 이후 실행에서도
동일한 `DIGITHIVE_DB`를 지정해야 복원된 자료를 계속 사용합니다.
서버 재시작과 스냅샷 파일에서의 복원은
`tests/engine/storage.test.ts`에서 실제 HTTP·SQLite로 검증합니다.

데이터 삭제는 현재 앱 데이터의 논리적 삭제입니다. 백업, 다운로드,
운영체제의 디스크 잔여 영역까지 안전하게 소거한다는 의미는 아닙니다.

## 외부 배포 (Docker + Caddy + HTTPS)

mini PC에서 Docker로 띄우고 이미 실행 중인 Caddy 뒤에 두어
`https://digithive.chanoil.com`으로 여는 방법은
[docs/deploy.md](docs/deploy.md)에 있습니다. 간단한 passphrase 게이트와
Caddy 스니펫, 보안 주의사항이 포함되어 있습니다.

`DIGITHIVE_PASSPHRASE`를 설정하면 passphrase 인증이 켜지고, 비워 두면
기존 로컬 전용 동작을 유지합니다. 공개 배포 시 `DIGITHIVE_PUBLIC_HOST`로
허용할 도메인을 지정하세요.

## 한 달 검증

[개인 실험 안내](docs/month-trial.md)를 따라 1주 기준선과 이후 비서 사용을
비교하세요. 기간 요약은 완전하게 기록한 날의 **일일 총 노력 중앙값 차이**를
보여줍니다. 맥락 복원·검색·재시작·검토·비서 관리·방해 복귀를 모두 포함합니다.
작업량 차이는 자동 보정하지 않으므로 비슷한 작업끼리 별도 비교해야 합니다.
승인·취소 위반과 근거 오류는 시간 절감과 별도로 판단하세요.

소프트웨어 검사 통과가 실제 한 달의 이득을 증명하지는 않습니다.
개인 한 명의 관찰로 다른 사용자에 대한 효과나 인과관계를 주장하지 않습니다.
