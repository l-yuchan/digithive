# 구현 전 부족점 점검

대상: `docs/assistant-v2-spec.md`. 이 문서는 제품을 실행한 QA 결과가 아니라, 상세 구현 계획 작성을 위한 근거와 부족점 기록이다.

## 유지해야 하는 방향

대화 중심, 독립 서버, 개인 일정 중심의 준비·브리핑, 실제 조사·초안 작업, 자동 기억과 정정, 내부 파일 접근, 스크립트·AI 혼합 실행, 명시적 외부 권한과 승인 후 환경 변경을 유지한다. 멀티에이전트의 수나 인격은 제품 요구가 아니다.

기존 `src/`를 새 구조에 억지로 맞추지 않는다. 기존 프로토타입을 보존하면서 새 애플리케이션 경계를 만든다. 삭제·데이터 이전·공개 배포를 계획 작성의 부수 효과로 실행하지 않는다.

## 외부 조건과 제안값의 구분

- 07:30·21:00과 Web Push는 사용자 요구다. `Asia/Seoul`은 제안값이다.
- 월 100달러 초과가 부담스럽다는 것은 사용자 기준이다. 70/90/100달러 자동 제어는 제안 정책이다.
- 15분 폴링과 하루 한 번 관심 검색은 제안값이다.
- 실제 서버 자원, 도메인, Google OAuth 설정, Canvas 서버 인증, 모델·검색 API Key는 아직 확보·검증하지 않았다.
- 계획은 이 값들을 설정 가능하게 하고, 실제 유료 호출·계정 연결·배포 이전에 필요한 확인을 명시해야 한다. 자격증명이 없는데 실제 연동 검증을 통과한 것으로 처리해서는 안 된다.

## 참고 문헌을 적용하는 범위

연구 노트의 CoALA·Generative Agents·MemGPT는 기억/검색/행동 책임 분리의 참고다. PROV-O·Event Sourcing은 출처와 정정 이력의 참고이며 해당 기술 전체의 도입 의무가 아니다. Mixed-Initiative는 침묵·지연·긴급 개입을 별도 결과로 다루는 참고다. Blackboard는 공유 작업 상태의 참고이며 고정 위계나 Git 조율을 강제하지 않는다. Reflexion과 CaMeL은 경험 저장과 실행 권한 변경을 분리하는 참고다.

## 조사와 검토의 상태

이 파일은 부모 에이전트의 직접 명세 대조로 작성했다. 독립 자문 결과와 최종 계획 검토는 별도 기록한다. 아키텍처 자문 한 건은 모델 제공자 HTTP 402로 실행되지 않았으며 승인 근거가 아니다.
