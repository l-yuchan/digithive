## Reproduction and causes

- At 390 x 844 with 30 long conversation titles, the original document was
  12,199 px wide. The mobile CSS changed the sidebar into an unconstrained
  horizontal list.
- `createHarness` registered no conversation tools. Production's latest saved
  response explicitly said it had no tools listed. The shared runtime now
  supplies read-only Gmail search and collected-data search to conversation
  and work execution. Live Gmail search uses the existing OAuth token-refresh
  path and reads message bodies.
- On mini, the web container had `HARNESS_SESSION_SECRET`; the worker did not.
  The worker therefore generated a different vault key and repeatedly wrote
  `google_not_connected`. The worker now receives the same required secret.
  Configuring Google without a shared secret fails at startup.
- A failed sync also overwrote the last successful collection timestamp. The
  existing later-page failure test reproduced that separately; failure now
  preserves the timestamp, snapshot and cursor while recording the real error.
- Desktop Firefox's reported push error has not been reproduced. A confirmed
  lifecycle gap is repaired: registration is awaited through activation before
  subscription, and existing subscriptions are reused. Visible diagnostics
  include phase, permission, exception details, worker state and browser data.
  Actual Desktop Firefox subscription/delivery remains unverified.
- Browser QA found an adjacent sidebar search defect: search returned only
  id/title while the client required session timestamps. The producer now
  returns complete sessions and also finds title-only matches.

## Supplementary proposals

Multi-account support requires account identity on credentials, source cursors,
collected rows and tool selection. Add independent mail/calendar switches per
account, keeping OAuth read permissions separate from collection choices.
Existing single-account rows need an explicit migration to an account ID.

For the schedule-first model, make persisted schedules the execution source:
one-shot or recurring triggers dispatch a script or an agent run. Keep schedule
configuration, each occurrence and its execution result separate, so a
multi-hour run does not occupy the conversation request. Reuse the existing
leased work queue for agent execution, and migrate current collection/briefing
timers into visible schedules. Conversation then manages schedules and explains
their state. These two architectural suggestions are assessed here for the
owner's confirmation, rather than silently changing the current domain model.
